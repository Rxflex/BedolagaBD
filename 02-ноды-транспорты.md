## 1. VLESS + Reality (TCP/raw) — базовый рецепт

Типовой инбаунд (шаблон чата):
```json
"inbounds": [{
  "tag": "NODA1_VPN_VLESS", "port": 443, "protocol": "vless",
  "settings": { "clients": [], "decryption": "none" },
  "sniffing": { "enabled": true, "destOverride": ["http","tls","quic"] },
  "streamSettings": {
    "network": "raw", "security": "reality",
    "realitySettings": {
      "show": false, "xver": 1, "target": "127.0.0.1:9443", "spiderX": "",
      "shortIds": ["XXXXXXXXXXXXXX"],
      "privateKey": "XXXXXXXXXXXXXXXXXXXXXXXXXXXX",
      "serverNames": ["domain.com"]
    }
  }
}]
```
[xid 114..~117, note_001; вариант note_020 id=114755+]

- Реверс-прокси вариант: `dest: "/dev/shm/nginx.sock"`, `xver: 1`, `spiderX: ""` [id=18313|note_004].
- «target — порт самой переадресации, который указывал при настройке selfsteal» [id=28441..28454|Egor|29.11.2025]: полный шаблон selfsteal — NL_VLESS_PROFILE port 443, target 127.0.0.1:9443, sniffing http/tls/quic; routing: block bittorrent / geoip:private / geosite:private; DNS 1.1.1.1/1.0.0.1.
- Спор про shortIds: Илья — для каждого юзера не нужен (UUID уникален, актуально для SS); Дмитрий — shortId в Client Hello отличает клиента Reality от обычного HTTPS и сокращает handshake [id=18313..18324|note_004].
- У некоторых клиентов отключалось: совет — network поменять с raw на tcp/tls, `target` → `dest`, стало лучше [id=18302|29.09.2025].
- «Реалити не охото оставлять — реалити сложнее блокировать по DPI» [id=28443|c0mrade|29.11.2025].

Генерация ключей на ноде:
```
docker exec <container_id> xray x25519 && openssl rand -hex 8
```
(privateKey — первый вывод, shortIds — последний hex) [id=note_017, ~10.12.2025].

Примеры target/serverNames из практики: `yandex.ru:443` + serverNames `yandex.ru,www.yandex.ru` [note_016]; `vk.com:443`, routeOnly true [note_018]; `max.ru:10000` (serverNames max.ru, www.max.ru) [id=196003|DONK|26.01.2026]; `yandex.ru:7443` [note_042]; `www.amd.com:443` [id=306460|30.03.2026]; `ads.x5.ru:443` + fingerprint chrome + `sockopt: {"tcpFastOpen": true, "tcpKeepAliveIdle": 100}` [note_057]; `st.ozone.ru:443` [id=636346|khanzele|04.06.2026].

Обход Reality для блокировок (ТСПУ-регионы): `realitySettings.dest = 1.1.1.1:443`, `serverNames = [""]` — работает в Приморском крае, Иркутской, Новосибирской обл. Профиль vless-reality-vision, port 443, sniffing routeOnly true, DNS cloudflare/google [id=71159,72142,72155|Камушек|23.11.2025].

Полный конфиг ру-ноды с балансировкой на 2 EU [id=699075|Руслан Иванов|15.06.2026]: inbound RU_IN (vless, 443, reality, dest ads.x5.ru:443, serverNames ads.x5.ru, fingerprint firefox, sniffing routeOnly http/tls/quic); outbounds EU_OUT_1/EU_OUT_2 (vless xtls-rprx-vision, reality, serverName www.amazon.com, fingerprint firefox), RU_DIRECT (freedom), RU_BLOCK (blackhole); routing: bittorrent→BLOCK, geoip:private→BLOCK, geoip:ru→RU_DIRECT, geosite:category-ru→RU_DIRECT, RU_IN→balancerTag EU_BALANCER; balancers: selector EU_OUT, strategy leastPing; domainStrategy IPIfNonMatch; policy connIdle 120, handshake 4, uplinkOnly 1, downlinkOnly 2; observatory probeUrl https://www.google.com/generate_204, probeInterval 30s, subjectSelector EU_OUT, enableConcurrency true.

## 2. Selfsteal (свой SNI)

- Selfsteal: поднять свой сайт вместо SNI google; на 443 спереди xray, за ним caddy/nginx с fallback на локалку. Маскироваться под свои сайты (иначе первый запрос = бан IP-хоста) [id=10360..10516|16.09.2025].
- Не прятаться под Google/8443; само-стил на 443 [id=439284|Stanislav Torichnev|27.04.2026].
- Caddy fallback + xray xhttp inbound: `edge.example.com: root /var/www/html file_server; handle_path /secretpath* reverse_proxy 127.0.0.1:10000` + xray vless xhttp security none, listen 127.0.0.1:10000, path /secretpath, host edge.example.com, outbound freedom [id=322178|vibes|04.04.2026].

## 3. SNI-подбор и fingerprint

- Критерии SNI (выдержка от Гемини [id=328197|MeinCain|06.04.2026]): домен должен поддерживать TLS 1.3 и HTTP/2, быть доступен с РФ-IP, не принадлежать конкурентам/блок-листам; «а вообще говорят, что еще лучше — selfsni» [id=328214].
- «Ставишь SNI РКН — и тебя не трогают» [id=328127|06.04.2026]; «меняй target на какой-нибудь github.com:443 и тестируй» [id=328135|Weelx|06.04.2026].
- Fingerprint-практика: chrome [note_014, note_057], firefox [id=699075], random [note_017], randomized (vless ws tls — «заведётся любая нода») [id=651697|pkhat|07.06.2026]. По fingerprint РКН вырезал всё: «редирект reality в браузере есть, в curl пусто, и ни один fingerprint не работает» [id=759521|27.06.2026].
- Билайн/Мегафон новые белые списки: проверка SNI + ASN (и вроде IP); в Татарстане (Мегафон) подтверждено, единственный рабочий метод — VK-туннель [id=15017|24.09.2025].

## 11. Роутинг (серверный/клиентский)

- Классические правила ноды: `geoip:private → BLOCK`, `bittorrent → BLOCK`, `geoip:ru → DIRECT`, `geosite:category-ru → DIRECT` [note_010, note_014, note_020].
- Серверный routing `{"ip": ["geoip:ru"], "outboundTag": "DIRECT"}` гоняет РУ-трафик через ноду (outbound freedom), не напрямую с телефона; клиентский DIRECT — только через клиентские роутинги [id=157287..157294, 157247..157249|09.11.2025].
- Happ routing (пример) [id=15648|Андрей|25.09.2025]: DirectSites/ProxySites (geosite: CATEGORY-GOV-RU, CATEGORY-MEDIA-RU, YOUTUBE, OPENAI, INSTAGRAM; DirectIp: private ranges + geoip:RU; DomainStrategy IPIfNonMatch, FakeDNS false).
- «Happ routing не юзаем — вместо него Xray json» [id=446374..446377|Frist|27.04.2026]; Happ-роутинг «гавно», роутинг через JSON Advanced [id=509443|14.05.2026].
- Серверный routing с leastPing-балансером (RUMSK/RUNSK inbounds → balancer → fallback DIRECT) [id=653971/654001|08.06.2026]:
```json
"routing": {"rules":[
  {"ip":["geoip:private"],"outboundTag":"BLOCK"},
  {"ip":["geoip:ru"],"outboundTag":"DIRECT"},
  {"inboundTag":["RUMSK_VLESS_INBOUND","RUMSK_Trojan_Inbound","RUNSK_VLESS_INBOUND","RUNSK_Trojan_Inbound"],"balancerTag":"Balancer"}],
 "balancers":[{"tag":"Balancer","selector":["PROXY"],"strategy":{"type":"leastPing"},"fallbackTag":"DIRECT"}],

```
- Клиентский роутинг на РУ-сервисы: огромный список доменов VK/OK/Mail/Dzen/Sber/Ozon/Avito/T-Bank/WB/Yandex/VTB/Alfa/RZD/Pochta/Gosuslugi/X5/HH → direct — «засерает память клиента» [id=654001|08.06.2026].

- Настройка БС по ip: geoip private покрывает часть, остальное в списке «224.0.0.0/3» [id=782775|kataomi|~02.07.2026].
- Gemini через WARP-outbound: домены gemini.google.com, generativelanguage.googleapis.com, aistudio.google.com и др.; можно geosite:google-gemini или category-ai-!cn [id=340457|хеуклер|08.04.2026].

## 12. Балансеры leastLoad / leastPing

- DNS-балансировка: истекший TTL убивает игровые сессии; лучше nginx/haproxy с healthcheck; лучше балансировать на клиенте: xray client json leastLoad/leastPing + observatory; DNS-рандом — «хуйня» [id=165648..165701|12.01.2026].
- Практика: leastLoad/leastPing по локам (5 РФ, 5 DE, 5 SE, 5 FI); «в json прилетит, но отображаться не будет» (галочка в ремне) [id=166929..166941|13.01.2026].
- Клиентская leastLoad предпочтительнее DNS-балансировки: leastPing кидает всегда на минимальный пинг, даже если сервер перегружен [id=188369|R0xTaDDy|22.01.2026]; «балансер будет скидывать людей на ту ноду, которая лучше отвечает, а не нагрузку распределять» [id=336269|Костя|07.04.2026]; «балансер выбирает по пингу» [id=333738|Frist|07.04.2026].
- Round-robin без привязки к TTL: в одном хосте ремны несколько адресов через запятую + предопределение; работает только при обновлении подписки, не динамически [id=188955/188954|Евген|22.01.2026].
- burstObservatory + leastLoad: 3 замера с таймаутом 2с, повтор каждые 3 минуты; leastLoad исключает пинг >1с и нестабильные >30% tolerance [id=232512|Haxonate|~21.02.2026].
- remnawave-cloudflare-nodes: скрипт мониторит API панели, добавляет/удаляет IP в DNS Cloudflare для node.example.com — github.com/hteppl/remnawave-cloudflare-nodes [id=235271|Евген|~22.02.2026].
- Anycast: «юзаем anycast и не паримся» [id=236300|Егор|~22.02.2026].
- XBM (Xray Balancer Middleware) 3.1.0→3.1.1 (платный, $200): leastLoad (задержка+потери), фейловер <1 мин, LTE-логика с tier-системой (основа → резерв tier1 → tier2), фильтрация по CPU/RAM/онлайну, Rate limit по HWID/IP, кэш подписки, sticky-session [id=486010|10.05.2026, id=509443|14.05.2026].
- Базовый leastLoad-балансер [note_060:218-226|06.04.2026]:
```json
"balancers": [{
  "tag": "EU_Balancer", "selector": ["proxy-"],
  "strategy": {"type": "leastLoad",
    "settings": {"maxRTT": "8s", "expected": 2, "baselines": ["1s"], "tolerance": 0.01}},
  "fallbackTag": "proxy"}]
```
- fallbackTag — один outbound tag, не список; резервные хосты задаются высоким cost [id=584231|art vs|25.05.2026, id=726376|Руслан Иванов|20.06.2026]:
```json
"balancers": [{
  "tag": "Super_Balancer", "selector": ["proxy","fallback"],
  "strategy": {"type": "leastLoad", "settings": {
    "costs": [{"match": "fallback", "value": 9999, "regexp": false}],
    "maxRTT": "1s", "expected": 2, "baselines": ["1s"], "tolerance": 0.01}}}],
"domainStrategy": "IPIfNonMatch"
```
- loopback = повторная отправка трафика обратно в routing; costs — выбор внутри одного балансировщика (cost:9999 = fallback участвует, но проигрывает живым) [id=587801|art vs|26.05.2026].
- Обсерватория с leastPing: переключает каждые 30с [id=587246|Иван Филиппов|26.05.2026]:
```json
"observatory": {"subjectSelector": ["VLESS_OUTBOUND_TO_FI","VLESS_OUTBOUND_TO_DE","VLESS_OUTBOUND_TO_NL"]},
"balancers": [{"tag": "EU_BALANCER",
  "selector": ["VLESS_OUTBOUND_TO_FI","VLESS_OUTBOUND_TO_DE","VLESS_OUTBOUND_TO_NL"],
  "fallbackTag": "BLOCK", "strategy": {"type": "leastPing"}}]
```
- leastPing vs leastLoad: leastPing — outbound с наименьшей задержкой на момент последней итерации обсерватории (одна проверка) [id=700857|Руслан Иванов|16.06.2026].
- leastPing + fallback + burstObservatory (HEAD, gstatic generate_204): balancer tag AUTO_FAST_EXIT, strategy leastPing, fallbackTag EXIT_SS_NETHERLANDS01; pingConfig timeout 3s, interval 30s, sampling 5, httpMethod HEAD, destination https://www.gstatic.com/generate_204 [id=462150|Peter|06.05.2026].
- Вариант пинга: pingConfig timeout 1s, interval 5s, destination http://www.msftconnecttest.com/connecttest.txt [id=627739|Николай|03.06.2026]; «не надо такой интервал — это слишком часто, 5сек» [id=629870|хеуклер|03.06.2026].
- remnawave injectHosts: selector type uuids (айди хостов не под БС), tagPrefix proxy, selectFrom ALL; БС-хост → tagPrefix reserve; DNS 1.1.1.1/1.0.0.1 queryStrategy UseIP [id=462987|06.05.2026].
- На iOS шаблон xray json балансера «затирает» конфиги одиночных хостов — проблема в hapе [id=646080|Илья|06.06.2026].
- Конфиг с балансером в INCY на iPhone не подключается (коннектит и обрывает), в Happ работает; в INCY балансерные хосты в одном проекте определяются как VLESS, в другом — как Shadowsocks и не пингуются (потом подтвердил автор) [id=749085..749210|26.06.2026, id=748107/748156, id=752154 «ждите фикса»].
- «Балансировка хостов с кучей edge-IP — нужно 30 хостов с одинаковыми настройками» [id=746613|26.06.2026].
- Лучший вариант: скрытый балансир «который сам кидает по разным протоколам подстать тому, что пользователю подходит в его сети» (дефолт leastLoad + инжект хоста) [id=782860|kataomi|~02.07.2026].
- Round-robin документация: https://xtls.github.io/en/config/routing.html#balancerobject (leastLoad, roundRobin) [id=761357|Руслан Иванов|17.06.2026].
