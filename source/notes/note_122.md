## Каскад RU gateway → EU exit (Caddy + Xray xhttp) — полный конфиг
- **[id=848912-848917|Данил|11.07.2026]** Схема: клиент → RU-сервер на 443 (Caddy) → по путям на inbound Xray (xhttp, listen 127.0.0.1) → outbound VLESS Reality (vision) на ноды PL/DE. Кадди хостит заглушку + reverse_proxy на 127.0.0.1:1050/1051 c `flush_interval -1` и `transport http { versions h2c }`.
- Проблема на DE-направлении: с телефона работает, с ПК браузер даёт «Ошибка при установлении защищённого соединения» — достоверность сертификата проверить не может (id=845425). Решения обсуждались: vlessRouteID (не делить по путям, меньше шансов ошибиться) — **[id=848875|x1roko]**, и проверка «что в 403 → фикс в закрепе».
- Клиентский конфиг RU-ноды (полный, ключи замазаны) — inbound два xhttp-порта (1050/1051), outbounds VLESS Reality на 192.0.2.1/.2 (порты 443), routing: block bittorrent + geoip:private, direct для geosite:category-ru / geoip:ru, затем inboundTag-направление.
- Нодовые конфиги PL/DE: Reality на target example.com:8443 (там кадди-заглушка), serverNames/shortIds/fingerprint edge; PL «там всё хорошо», DE с 403/ошибкой сертификата — несогласованность сертов/заглушки.

## DNS-роутинг в INCY — сломан относительно других клиентов
- **[id=843810/844763|Артём Соломатин]** Если в конфиге Xray прописан блок `dns` (встроенный DNS-аутбаунд с dns-proxy/dns-direct), то в INCY ДНС-запросы вообще не попадают в роутинг и идут напрямую; в Happ/v2rayN/голом ядре работает по документации Xray. Решение для INCY — убрать `dns` из конфига и пустить все запросы через прокси; точное разделение по доменам не получится. Полный JSON конфиг с dns-proxy(1.1.1.1)/dns-direct(8.8.8.8, geosite:category-ru, skipFallback) и routing-правилами (port 53 → dns, ip geoip:private/ru → direct, geosite:category-ru → direct, tcp,udp → proxy) приведён дословно (id=843810).
