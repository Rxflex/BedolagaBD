## Проблема iOS + XHTTP (404) и фикс
- Симптом: на iOS (Happ, Xray 26.7.11, ядро обновлено) сервера под XHTTP не подключаются; в логе `transport/internet/splithttp: unexpected status 404` и `failed to send upload: bad status code:404 Not Found`; обычные (Reality) работают [id=912359|Egoist 潔 世].
- Причина: те, кто изначально криво настроил Xray-ноду (голый xray наружу), после обновления ядра ломаются; то же скоро в Happ [id=912500].
- Фикс: клонировать хост в панели (клонировать рабочий хост), в дополнительных параметрах добавить `/` в конец пути (path), и проверить [id=912488..912498]. Прямое копирование JSON из Happ в INCY без клонирования хоста — не работает [id=912495..912497].

## Защита от DDoS — рассуждения
- Мелкому сервису платить за DDoS-защиту (решения/откуп) смысла нет; для мелких «падло — заплати 500р, возьму новую ноду». Крупному (20-40к?) — лучше зеркалировать подписки, чем тратить на «решения»; «каскады» — бред из раздела приколов [id=912371..912400].
- ДДоС стоит копейки; у большинства в РФ — не свои ботнеты, а китайские стрессеры/Ц2 [id=912405..912423].
- Для BS нужен хороший канал изначально + защита до твоего хопа [id=912374].

## Certbot/guide-критика (Колян)
- Типовой блогерский гайд: сертификаты в /opt/certbot/certs вместо стандартного /etc/letsencrypt; крон на renew каждое 28-е число вместо ежедневного запуска (Let's Encrypt рекомендует 1-2 раза в день; запуск каждый час не нагружает сервер) [id=911094].
- Крон-строка из гайда (дословно, [id=911128|Колян]):
```
0 5 * * 0 ufw allow 80 && /usr/bin/certbot renew --quiet && ufw delete allow 80 && ufw reload && cd /opt/remnanode && docker compose down && docker compose up >> /usr/local/remnawave_reverse/cron_jobs.log 2>&1
```
- Критика: скрипт в 90 дней сломается; docker-подход делает инструкцию не зависимой от хоста, но «быстро, чем удобно»; ремнейв-ноды через docker compose down/up — ненадёжная связка [id=911094, 911097, 911118, 911128, 911172..911176].
