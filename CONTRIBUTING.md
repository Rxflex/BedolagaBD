# Как дополнять базу

[⌂ База знаний](README.md) · [🗺 Карта](MAP.md) · [📖 Термины](indexes/термины.md) · [🤖 Для агентов](AGENTS.md)

База живёт по одному правилу: **нет пруфа — нет записи**. Ниже — что это значит на практике.

## Главное в трёх пунктах

1. Правятся только `docs/**` и `indexes/термины.md`. Всё остальное — производное, пересобирается скриптами и ваши правки там затрутся.
2. Каждый факт снабжается пруфом `[id=N|автор|дата]` — номером сообщения в чате. Без него факт не принимается.
3. Даты абсолютные (`ДД.ММ.ГГГГ`). Рецепт без даты бесполезен: в этой теме половина методов живёт два месяца.

## Формат записи

```markdown
- **Что случилось или что делаем** [id=698034|Ник|16.06.2026](https://t.me/c/2941121338/698034) — суть одной фразой.
  ```bash
  # конфиг или команда — дословно, без пересказа
  docker compose up -d --build
  ```
```

Правила формата:

| Правило | Почему |
|---|---|
| Конфиги и команды — дословно | Пересказанный конфиг не запускается |
| Один факт — один пункт | Иначе получается простыня, которую невозможно читать |
| Ссылочные каталоги — таблицей `Что \| Ссылка \| Пруф` | См. [01 Ссылки и инструменты](docs/01-панели/ссылки-инструменты.md) |
| Голые URL оформляем как `[owner/repo](ссылка)` | Длинный URL ломает читаемость строки |
| Устаревшее не удаляем, а датируем | История «что когда работало» — половина ценности базы |
| При противоречии оставляем обе версии | Чат не всегда сходился во мнениях, и это факт |

## Приватность

Репозиторий публичный, а материал — из приватного чата. Поэтому:

- **Не добавляйте полные имена.** В базе только ники и формат «Имя Ф.» — обезличивание автоматическое, см. [`_tools/sanitize.py`](_tools/sanitize.py).
- **Не добавляйте секреты.** Токены, приватные ключи, пароли, реальные `SHOP_ID`, содержимое чужих `.env` — заменяются заглушками вида `<32-hex, openssl rand -hex 16>`.
- **Не палите чужую инфраструктуру.** Открытые панели, адреса конкурентов, «вышли на такого-то» — не контент базы.
- Телефоны, карты, паспортные данные, адреса — не добавляются никогда.

Перед коммитом прогоните скан: `python _tools/pii_scan.py --samples`.

## Порядок работы

```bash
# 1. правки в docs/
# 2. пересборка производного
python _tools/build_nav.py        # шапки, подвалы, хабы разделов, MAP.md
python _tools/build_indexes.py    # индексы релизов, ошибок, env, ссылок

# 3. оформление (идемпотентно)
python _tools/prettify_links.py   # голые URL → компактные ссылки
python _tools/link_proofs.py      # [id=N] → ссылка на сообщение
python _tools/sanitize.py         # обезличивание и заглушки секретов

# 4. проверки перед PR
python _tools/check_links.py      # все внутренние ссылки и якоря
python _tools/pii_scan.py         # утечки
```

Те же проверки гоняет CI на каждый PR — [`.github/workflows/checks.yml`](.github/workflows/checks.yml).

## Новый документ в разделе

1. Добавьте запись в `SECTIONS` в [`_tools/kb_lib.py`](_tools/kb_lib.py): имя файла, человеческое название, короткое описание.
2. Создайте сам файл в нужной папке `docs/NN-.../`, начните с `# Заголовок`.
3. Прогоните `python _tools/build_nav.py` — шапка, оглавление, подвал и ссылки в хабе появятся сами.

## Новый раздел

Отдельный раздел — это запись в `SECTIONS` с папкой, эмодзи и акцентным цветом. После добавления прогоните `build_nav.py` и `build_assets.py` — баннер раздела сгенерируется автоматически.

## Что в базу не идёт

Мемы, флуд, личные перепалки, реклама услуг без фактов опыта, пересказ документации проектов (вместо этого — ссылка), любые данные, которые нельзя подтвердить сообщением из чата.
